# Simulation review: Bonding and Spectroscopy group

Review date: 2026-11-16. Read-only review; no source, test or config file was changed.
Scope: `bonding-visualizer`, `hybridisation-explorer`, `intermolecular-forces-visualiser`, `vsepr-explorer-3d` (full review) and `spectroscopy-studio` (NMR, IR, MS, Structure Investigation; light touch).
Evidence screenshots: `/tmp/simreview/bonding/` (referenced by file name below; `verify/` holds a partial run of the existing Bonding script).

## 0. How this was done, and what it can and cannot prove

- Built the app to a temp dir (`vite build --outDir /tmp/elab-dist`), served with `vite preview`, drove it with Playwright + headless Chromium (SwiftShader). Viewports 1366x768, 820x1180, 1024x700, 390x844 (touch/mobile emulation). Probed: every VSEPR preset (17) in both views with sim angles read from the live simulation state, free-build edge cases, drag-to-perturb, challenge flow, rapid tab/molecule switching, zoom extremes, CSS fullscreen, resize; Bonding ionic/covalent/metallic including refusals, 8-atom cap, 200-atom metallic, lattice, mid-animation reset, tab hammering; Hybridisation Lab (ground/excited, sp2/sp3, add atom) and all 11 Molecule Explorer sequences stepped to the end with sigma/pi counts compared to the stated expectation; IMF Explore (force x pair combinations), Learn, Heat (water solid to gas and back, rapid substance switching, reset), Compare; Spectroscopy tab and step walk-through; WebGL-disabled behaviour for all five (context patched to return null).
- Console: no application errors or React warnings in any run. The only console error is a blocked request to `fonts.googleapis.com` (sandbox has no external egress). Warnings are SwiftShader driver notices and a three.js `THREE.Clock` deprecation notice.
- **Font caveat:** because Google Fonts was blocked, every screenshot uses the local fallback font (Inter), not the production font (IBM Plex Sans per `index.html`). Anything font-dependent is flagged as such.
- **Not testable here:** real GPU performance (SwiftShader fps numbers are meaningless for GPUs and are not used for any claim), real touch devices, Safari/Firefox, screen readers, real native fullscreen.
- **Previously known findings not repeated:** fullscreen/new-tab controls, layout-overflow matrix and button contrast (`docs/SIMULATION_AUDIT_REPORT.md`), per-simulation "Not verified" lists. That audit did not examine chemistry content, pedagogy, fallbacks or accessibility of the 3D views, so almost everything below is new.

## 1. VSEPR Explorer (3D) (`vsepr-explorer-3d`)

**Verdict.** The strongest model in the group. Geometry names, AXE notation, domain counting (double/triple bond = one domain) and all 17 preset angles are right and consistent between the info panel, Lewis view and the 3D relaxation (I read the simulated angles from the live state: NH3 107.0, H2O 104.5, SF4 173.1/101.6, ClF3 175.0/87.5, XeF4 and SF6 exactly 90/180). The drag-a-domain-and-watch-it-relax interaction with live angle read-outs is genuinely premium. What stops it being flawless: the molecule list disappears below ~900 px (the primary control on phones and tablets), atom labels are clipped by their own spheres, angle labels collide on the AX4E/AX5E shapes, the library lacks ions and polyatomic species that the IB course examines, and the free-build mode names chemically impossible species as if they were real.

**Premium-readiness: 7 / 10.** Chemistry core 9/10, interaction 8/10, but a blocker-class layout bug on small screens, a content gap (ions) and weak challenge/accessibility keep it from 8+.

## 2. Bonding Visualizer (`bonding-visualizer`)

**Verdict.** Clean, honest and carefully scoped (it refuses unsupported combinations with an explanation instead of inventing one; AlCl3/AlN refusal, lattice only for validated structures, ionic radii correct to the data booklet values I remember). Ionic and metallic modes work well and the covalent Lewis-with-shell-overlap animation is clear. But as a premium *teaching* product it is thin: 12 covalent molecules, no CO2 or any double-bonded polyatomic, no coordinate bond, no resonance, no polarity or electronegativity (by design, `docs/BONDING_VISUALIZER.md`), no predict/check layer, a blank first screen, tiny atoms on phones, and a non-functional metallic mode without WebGL.

**Premium-readiness: 6 / 10.** Technically sound (no errors in any probe), but content depth and pedagogy are below the other three simulations in this group.

## 3. Hybridisation Explorer (3D) (`hybridisation-explorer`)

**Verdict.** The most visually impressive of the group and the most scientifically careful: orbitals are generated from real angular functions, hybrids come from the textbook orthonormal coefficient sets with computed directions, electron counts are conserved, and every one of the 11 molecule sequences ended with the stated sigma/pi count (H2 1/0, HF 1/0, CH4 4/0, NH3 3/0, H2O 2/0, C2H6 7/0, C2H4 5/1, C2H2 3/2, H2CO 3/1, CO2 2/2, C6H6 12/0 + delocalised pi). Honest disclaimers ("illustrative promotion", "educational angular part only") are present. Weaknesses are scope (d-orbital hybrids that the IB course does not teach), a missing validation hint for chemically odd mixes, a short molecule list that omits the IB staples (BF3, BeCl2, HCN, ethanol), and visual clutter once a molecule is fully assembled.

**Premium-readiness: 7 / 10.**

## 4. Intermolecular Forces Visualiser (`intermolecular-forces-visualiser`)

**Verdict.** The physics model is better than a typical teaching sim: induced dipoles from fields, correlated London fluctuations (with the spinning-cloud bug already fixed per the docs), an H-bond criterion based on H...A distance, X-H...A angle and lone-pair alignment (HCl correctly refused as donor, CO2 correctly "polar bonds but no net dipole"), and a heating model with plateaus using values that match the CRC/NIST numbers I remember. The Learn lessons are polished. Where it falls short of "premium" is the exam-facing use of IMFs: there is no way to *rank* substances or boiling points, no predict/quiz, the heating cube is hard to read, the first screen shows nothing happening, and without WebGL nearly everything is an empty panel.

**Premium-readiness: 6.5 / 10.**
