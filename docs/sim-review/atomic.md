# Atomic-structure simulations: premium-readiness review

Scope: `build-an-atom`, `electron-configuration` (Electron Configuration Explorer and its periodic-table picker), `orbital-explorer`, `wave-explorer`, `atomic-spectra-lab`, `ionization-energy-explorer`.
Review type: read-only. No source, test, config or package file was changed. Screenshots and probe scripts are under `/tmp/simreview/atomic/` (scripts and logs in `/tmp/simreview/atomic/probe-scripts/`).

## 0. How this review was done, and what it does not cover

Known findings were read first (`docs/SIMULATION_AUDIT_REPORT.md`, `docs/BUILD_AN_ATOM.md`, `docs/UNIVERSAL_AUDIT_SPEC.md`) so that layout/fullscreen/control-presence problems already fixed are not repeated. That audit was about presence of controls and layout; it explicitly did not re-verify scientific content ("preserved, not changed"). This review is mostly about science, validation, pedagogy and polish.

Done:
- Read all engine code and data files for the six simulations.
- Built the app twice (production, and `NODE_ENV=development` unminified for React warnings) and drove it in headless Chromium (Playwright, SwiftShader) at 1366x768, 1024x768, 910x512 (150 % zoom emulation), 820x1180 and 390x844, plus `prefers-reduced-motion`. Console was watched in the dev build for all six: no React warnings or page errors were produced by any probe.
- Hostile inputs: extreme particle counts, rapid clicking, double-click on actions, Reset / element change mid-animation, huge/negative/non-numeric typed values, search with junk, `+1000` spam.
- Pure-logic checks run in Node against the real modules: orbital sampling (mean radius against hydrogenic theory), nuclide/ion configuration logic, absorption matching, all 118 configurations (sum = Z, subshell capacities).
- Existing suites `scripts/test-build-atom-controls.mjs` (23 pass) and `scripts/test-electron-config.mjs` (13 pass) were run unchanged.

Verified externally (WebFetch of the Wikipedia ionization-energy data page, which tabulates NIST/CRC values): successive ionization energies of Na, Mg, Al, Si, S, K, Ca, and first/second IE of H and He (H and He are absent from the simulation, see IE-02). Syllabus statement wording S1.3.1 to S1.3.8 was taken from a third-party transcription (yueyuan-org.pages.dev), not from the IB guide itself; please treat the statement numbers as "to be confirmed against your copy of the guide".

Reasoned only, not externally verified: nuclide stable/radioactive lists (matched against my own knowledge of NUBASE/CIAAW; the file's header cites those sources), first IE of Li to Ar and the successive values of the elements not listed above, the electron-configuration exception list (Cr, Cu, Nb, Mo, Ru, Rh, Pd, Ag, La, Ce, Gd, Pt, Au, Ac, Th, Pa, U, Np, Cm, Lr matches the commonly published set; I did not check all 118 against NIST line by line), IB data-booklet constants.

Not covered: real GPU frame rates (SwiftShader is not representative; where I quote slow timings they are software-rendering numbers), Safari/Firefox/WebKit, real touch devices, screen readers (only DOM roles/labels inspected), keyboard orbit control of the 3D canvas, the Learn-embedded mode with live Supabase, native fullscreen.

## 3. Build an Atom (`src/engines/build-an-atom`)

**Verdict (5/10).** The code is tidy, has a single source of truth for the three counts, a genuine "what changed" explainer, an honest stable/radioactive/not-stable classification, reduced-motion support (verified: zero running animations), no horizontal overflow at 390 px, and sensible tests. It falls short of premium on exactly the point the owner raised: limits are arbitrary rather than physical. Neutrons run 0-60 for every element, so Hydrogen-61 is one long press away and is merely labelled "Not a stable nuclide", which is misleading because no such nuclide exists. Protons 0-36 with electrons 0-40 allow Kr with a 4- charge. Ion configurations are wrong for the d-block, a clear conflict with S1.3.5 (configurations of atoms and ions to Z = 36). The side panel's sticky block still covers controls at 150 % zoom (open item from the earlier audit, reproduced). Pedagogy is a fixed set of eight challenges and static concept cards. It does not reach the S1.2 content a teacher needs most (relative atomic mass from isotopic abundance).

## 4. Electron Configuration Explorer (`src/engines/electron-configuration`)

**Verdict (4/10).** Data are right: all 118 configurations sum to Z with subshell capacities respected; the exception list matches the commonly published set (Cr, Cu, Nb, Mo, Ru, Rh, Pd, Ag, La, Ce, Gd, Pt, Au, Ac, Th, Pa, U, Np, Cm, Lr) and Lr uses the 7p1 assignment. The experience around the data is weak, and the catalogue promises something it does not do ("one electron at a time"). In the student flow the Construct step lists exactly the subshells of the correct answer and asks only for the counts, so the hard part (which subshells, in which order, with which exception) is given away; Hund's rule and the Pauli principle are never exercised because orbital boxes are only shown after success or Reveal. Check accepts all zeros, shows no total-versus-Z feedback and never explains an exception. Ions, which S1.3.5 requires, are not available although the code to compute them exists. The 118-cell table fills the whole first screen so the exercise starts below the fold. Teacher mode shows a "shell diagram" with count badges stacked at 12 o'clock rather than electrons. Configuration text has no superscripts and no noble-gas shorthand.

## 5. Orbital Explorer (`src/engines/orbital-explorer`)

**Verdict (4.5/10).** The maths is the strongest part. I sampled 40,000 points per orbital in Node and compared the mean radius with the hydrogenic expectation: 1s 1.51 (1.5), 2s 5.98 (6), 2p 4.98 (5), 3s 13.3 (13.5), 3d 10.4 (10.5), 4s 23.2 (24, about 5.6 % of density is clipped by the 36 a0 bounding radius). Sampling is fast (about 0.2 s for 10 orbitals x 10,000 points). The product around it is below standard. Every element in Build mode uses hydrogen (Z = 1) orbitals, so carbon's 1s is as large as hydrogen's and everything is drawn as one overlapping blob that is unreadable for calcium; this is not disclosed. The detection count has no cap. "Boundary Surface and Cross-section are not yet available" is visible to students. The non-1s orbitals open at 400 points, which cannot show a shape. The nucleus is a 0.35 a0 sphere. A mode named "Build an Atom" clashes with the S1.2 simulation of the same name.

## 6. Wave Explorer (`src/engines/wave-explorer`)

**Verdict (4/10).** It is clean and the relationships it states (c = f lambda, E = hf, amplitude independent of frequency) are right, and the text feedback is generated from real state. But it is the least ambitious of the set and has visible defects. The wavelength is locked to 400-700 nm, so the EM spectrum that the rest of S1.3 relies on (UV in Lyman lines, IR, X-ray, radio) cannot be explored and the other atomic simulations cannot link to it. The amplitude slider at 0 still draws a wave 14 px high while the readout says 0.00. The longitudinal wave at high amplitude has particles passing through each other (maximum displacement 46 px against a particle spacing of about 12 px and a wavelength of 50 px) and, worse, quotes a wavelength in nanometres for what is meant to be a mechanical wave. The wave is a fixed indigo line, not coloured by wavelength, so the link to visible light colours that the Atomic Spectra Lab uses is absent.

## 7. Atomic Spectra Lab (`src/engines/atomic-spectra`)

**Verdict (5/10).** The physical model is good where it is used: hydrogen levels from E = -13.6/n^2, Balmer wavelengths within 0.03 % of the air literature values (656.47 vs 656.28 nm, 486.27 vs 486.13, 434.17 vs 434.05, 410.29 vs 410.17, computed in Node), a three-way outcome for absorbed / ionised / not absorbed, and a Linked View. ## 9. Proposed improvement plan

### 9.1 Build an Atom
- Keep: the three-count single source of truth, the "informative, never blocking" philosophy (but move the blocking line to physically impossible nuclei), auto-balance, What Changed panel, reduced-motion support, tests in `scripts/test-build-atom-controls.mjs`.
- Rebuild: limits (BA-01/02/04), ion configuration (BA-03), Compare Isotopes dialog (BA-05), the sticky side panel (BA-06), and the particle renderer (BA-10).
- New features that would feel premium:
  - A band-of-stability gauge: an N versus Z mini-chart with the current nucleus as a dot, stable region shaded, drip-line edges; when the student pushes beyond the edge, the dot turns red and a sentence explains ("too many neutrons: beta-minus decay likely; heaviest known hydrogen isotope is H-7").
  - Honest labels: "Stable", "Radioactive (half-life ...)", "Observed, very short-lived", "Never observed". Half-lives for the common ones (C-14, H-3, K-40, I-131, Co-60).
  - "Isotope mixer" to compute relative atomic mass from abundances with the working shown (BA-08), with a button to open the Mass Spectrometry simulation.
  - Rule-generated challenges and a short worked solution (BA-07).
- Order: BA-01/02/03 first (one day with a shared data module), then BA-06/05, then the mixer, then renderer swap.

### 9.2 Electron Configuration Explorer (and the periodic table)
- Keep: `buildConfiguration` and the exceptions table, the student/teacher split, hint ladder.
- Rebuild: the Construct step (EC-01), notation (EC-05), layout (EC-06), the periodic-table component (EC-07/08, shared per X-01).
- New features:
  - Electron-by-electron builder on an energy-ordered diagram (decoy subshells included), with refusal reasons that quote the rule ("Pauli: an orbital holds at most two electrons of opposite spin").
  - Orbital boxes that appear as soon as electrons are placed, with Hund's rule violations highlighted rather than prevented in an "explore" mode.
  - Ion mode (EC-04) with the 4s-first removal story and Fe2+/Fe3+, Cu+, Cr3+ as named examples.
  - Exception explainer for Cr and Cu (and the IB-relevant ones to Z = 36), plus "spot the exception" quiz.
  - A proper periodic table: group/period headers, block colours, tooltip with name/Z/configuration shorthand, shading outside Z <= 36, keyboard navigation, search with Enter.
- Order: shared periodic table and ion maths, then electron-by-electron builder, then quiz.

### 9.3 Orbital Explorer
- Keep: the sampling maths (verified), seeded repeatable clouds, the legend/isolate idea, the quality tiers.
- Rebuild: Build mode presentation (OE-02), the boundary layer (OE-05), the detection-count handling (OE-03).
- New features:
  - A "measure the electron" mode: points appear in batches and the cloud builds up while a counter shows "n detections" (default sensible counts per orbital, OE-04).
  - Radial probability plot beside the 3D view with the node(s) marked; 1s/2s/3s overlay.
  - Phase colouring (+/-) and iso-surface at 90 %; cross-section slice with a slider.
  - Effective-nuclear-charge scaling or a visible "shapes only, not sizes" note (OE-01).
  - Show all three p orbitals together with the axes; a "d orbitals gallery".
- Order: OE-03 and OE-04 and OE-07 (small), then OE-01, then iso-surfaces and radial plot.

### 9.4 Wave Explorer
- Keep: the c = f lambda / E = hf messages generated from state, the clean transverse drawing with tracked annotations.
- Rebuild: wavelength scope and control (WE-01), amplitude mapping (WE-02), longitudinal model (WE-03).
- New features:
  - EM-spectrum bar from gamma to radio with the current wave marked and region names; visible-light colour strip.
  - "Compare two waves" mode with predict/reveal (which has higher energy, which is faster?).
  - Link out: "this is the photon of Balmer alpha" opening the Spectra Lab at that transition.
  - Photon energy in J, eV and kJ mol-1.

  - Series chips (Lyman, Balmer, Paschen) and a convergence zoom; "find the ionisation energy from the series limit".

## 10. Questions for the owner

1. Build an Atom limits: should the default be strict (only known isotopes and charges up to about +/-4 allowed, with a "sandbox" switch) or permissive-with-warnings (current philosophy)? For Hydrogen-8 or Kr4- do you want refusal or a red "does not exist" state?
